# tests/expected-links.txt
#
# The exact set of BPF links `compartment-bpf --pin` must leave under
# /sys/fs/bpf/compartment/links, one name per line.
#
# smoke-pin returned rc=0 for every one of six mutations that disabled an
# enforcement program (inode_set_acl, file_ioctl_compat, sb_mount,
# move_mount, sb_umount, bprm_committed_creds): the loader starts cleanly
# with one fewer link, the pin path never counted them, and nothing else
# in the pin layer looked. The CHANGELOG's "28 links attached" had no
# gate at all.
#
# comp_file_ioctl_compat is conditional: on a kernel without
# security_file_ioctl_compat() the program is not autoloaded and the pin
# is skipped, which is correct — compat ioctls route through
# security_file_ioctl() there. It is marked below and the assertion keys
# it off the loader's own "[probe] file_ioctl_compat hook: present|absent"
# line, so the check is exact on both 6.8 and 7.0 rather than a count
# with a tolerance.
#
# comp_inode_setattr is pinned under that canonical name whichever of the
# two kernel-signature wrappers is live.
#
# Adding or removing a hook means changing this file in the same commit.
